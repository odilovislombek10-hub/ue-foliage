# Client decisions (binding for the lighting/visualization integration)

- 2026-09-29: Sun is chosen PER SHOT to suit the frame. For each hero camera: sun 40–120° to the side / three-quarter back relative to the view direction, elevation ~35–45°, so buildings get one lit and one shaded face and shadows are long. Keep the clock near 13:00 where possible; adjust the UDS date (e.g. Oct 1–15 gives 39–44° at 13:00) and/or north/sun rotation as needed. Foliage stays summer via the 'UDW Seasons' MPC (independent of date).
- Look target: <referens papka>/825e3a246161a4adddf5940f05e2e91a.jpg (bright lively midday, warm sun, cool open shadows, gentle haze), rendered from above (client camera in user_camera.json, ~546 m, pitch -39°; shots A–E in camera.md).
- Rendering: NO offline renders / stills / Movie Render Queue / path tracing. The deliverable is a PACKAGED real-time ArchViz Explorer build (kiosk + walkthrough). Everything must work at runtime in the packaged game: settings live in Config/*.ini (DefaultEngine/DefaultScalability/DefaultDeviceProfiles), in-level actors (UDS, PostProcessVolume, lights) and runtime CVars applied by the game — not editor-only Python. Target: Lumen GI + ray-traced shadows (or VSM where it is the better real-time choice) at acceptable FPS for the huge scene. "Top-down" aerial views are interactive camera views, not stills.
- Planting: trees and shrubs only, no flowers, no ornamental grass.
